# نظام التحميل الذكي المتكيف مع أبعاد الشاشة والجلب الاستباقي للصور (Viewport-Aware Image & Grid Pipeline)

بناء منظومة تحميل متجاوبة تقيس أبعاد نافذة المتصفح (`Width × Height`) لحظياً لتحديد العدد الدقيق للمنتجات الظاهرة في الشاشة الأولى (Above the Fold)، وعرض صورها فوراً بأولوية قصوى (`loading="eager"`, `fetchPriority="high"`)، ثم البدء تلقائياً في الجلب الاستباقي للدفعة التالية وصورها في الخلفية لضمان تمرير فوري خالٍ من أي تأخير.

---

## قرارات التصميم المعتمدة (Confirmed User Decisions)

> [!IMPORTANT]
> تم اعتماد التفضيلات الهندسية التالية بناءً على اختياراتك لتوجيه التنفيذ:

- **حساب ديناميكي بالكامل حسب عرض وارتفاع النافذة**: تحديد عدد أعمدة الشبكة وعدد الصفوف المرئية فعلياً بناءً على أبعاد الشاشة الحالية (`innerWidth × innerHeight`) بحيث تُحمّل الدفعة الأولى فوراً على قدر المساحة المرئية (مثل 4 منتجات على شاشات الجوال، و8–10 على التابلت، و12–20 على شاشات الحاسوب حسب ارتفاع الشاشة).
- **جلب استباقي للدفعة التالية بالخلفية فور ظهور الدفعة الأولى**: بمجرد استقرار وعرض منتجات الشاشة الأولى، يبدأ النظام تلقائياً بتحضير الدفعة التالية وترطيب وفك ترميز صورها (`Background Image Pre-decoding`) في الخلفية قبل أن يبدأ الزائر بالتمرير.
- **تحميل فوري بأولوية قصوى للدفعة الأولى وكسول ذكي للبقية**: منح بطاقات الشاشة الأولى فقط أولوية الشبكة القصوى (`loading="eager"` و `fetchPriority="high"`) لتجنب تزاحم الطلبات الشبكية، بينما تُحمّل البطاقات اللاحقة بوضع كسول ذكي (`loading="lazy"`) مدعوم بالجلب المسبق في الذاكرة المؤقتة للمتصفح.

---

## 1. نظرة عامة والقيمة المضافة (Overview & Core Value)

- **ما الذي يقدمه التحديث**:
  - يمنع اختناق الشبكة على الهواتف عبر عدم طلب 20 أو 40 صورة دفعة واحدة في اللحظة الأولى، والاكتفاء بطلب وعرض منتجات الشاشة الأولى المرئية فوراً في أقل من جزء من الثانية.
  - يضمن عدم شعور المستخدم بأي تقطيع عند النزول لأسفل الصفحة بفضل الجلب الاستباقي الخلفي الذي يجهز الدفعة الثانية فور انتهاء رسم الدفعة الأولى.
- **المستفيدون**: زوار المتجر عبر الهواتف الذكية (خصوصاً على شبكات الجيل الرابع أو الاتصالات المتفاوتة)، والأجهزة اللوحية، وشاشات الحاسوب العريضة.

---

## 2. تجربة المستخدم والهوية البصرية (User Experience & Visual Design)

- **مسار التحميل والتفاعل (User Flow)**:
  1. **اللحظة صفر (قياس النافذة - Viewport Detection)**: يحسب المتجر عدد الأعمدة والصفوف التي تملأ الشاشة الحالية بدقة.
  2. **الظهور الفوري للشاشة الأولى (Instant First Fold)**: تظهر المنتجات المرئية الأولى مع صورها الحقيقية مباشرة دون أي صندوق كرتوني مؤقت أو انتظار لبقية الكتالوج.
  3. **التحضير الخلفي الصامت (Silent Background Warm-up)**: أثناء مشاهدة الزائر للمنتجات الأولى، يقوم المتصفح في الخلفية بجلب بيانات وصور الدفعة التالية وتخزينها في ذاكرة الصور المؤقتة (`Image Decode Cache`).
  4. **التمرير الانسيابي اللانهائي (Zero-Lag Infinite Scroll)**: عند نزول الزائر، تندمج الدفعة الجاهزة فوراً، ويقوم مراقب التقاطع (`IntersectionObserver`) بطلب الدفعة التي تليها قبل الوصول لنهاية القائمة بمسافة كافية، مع مضاعفة حجم الدفعة تلقائياً عند التمرير السريع.
- **الاتساق البصري والهوية**:
  - الحفاظ الكامل على الهوية البنفسجية الملكية الداكنة لمتجر أحمد بحري (`#5b21b6`، `#2e1065`)، ومؤشر التحميل السفلي الأنيق («جاري تحميل المنتجات...»)، وثبات أبعاد البطاقات لمنع أي إزاحة بصرية (`CLS = 0`).

---

## 3. القرارات الهندسية والمفاضلات (Key Product Decisions & Trade-Offs)

- **القرار 1: فصل حجم الشاشة الأولى (`initialFoldCount`) عن حجم دفعات التمرير (`scrollBatchSize`)**
  - *النهج المختار*: جعل الدفعة الأولى مقتصرة على ملء الشاشة المرئية فقط (مثلاً 4 بطاقات للجوال) لتركيز كامل عرض النطاق الترددي (Bandwidth) على الصور التي يراها المستخدم فعلياً، ثم استخدام دفعات تمرير أكبر في الخلفية.
  - *السبب*: طلب 20 صورة بوضع `eager` في نفس اللحظة على الجوال يوزع سرعة الإنترنت على 20 اتصالاً متزامناً فيؤخر ظهور أول 4 صور؛ بينما حصر الأولوية القصوى في الشاشة الأولى يجعلها تظهر لحظياً.
- **القرار 2: فك ترميز الصور مسبقاً في الخلفية (`Async Image Pre-decoding`)**
  - *النهج المختار*: استخدام كائنات `Image()` غير مرئية مع `decoding = "async"` و `img.decode()` للدفعة التالية فور اكتمال الدفعة الأولى.
  - *السبب*: عندما يصل المستخدم بالسكرول إلى البطاقات الجديدة، تكون الصور محملة ومفكوكة الترميز جاهزة للرسم الفوري في إطار واحد (`16ms`).

## 4. البنية المعمارية وتدفق البيانات (Technical Architecture & Data Flow)

```
┌────────────────────────────────────────────────────────────────────────────┐
│                   Viewport Geometry Engine (Window W × H)                  │
│  • Calculates active grid columns (1 / 2 / 3 / 4) & visible card rows      │
│  • Outputs: initialFoldCount (First Fold) + scrollBatchSize (Next Chunks)  │
└─────────────────────────────────────┬──────────────────────────────────────┘
                                      │
                                      ▼
┌────────────────────────────────────────────────────────────────────────────┐
│                 Adaptive Storefront Feed & Cache Pipeline                  │
├─────────────────────────────────────┬──────────────────────────────────────┤
│   Stage 1: Instant First Fold       │   Stage 2: Background Pre-Fetcher    │
│   (index < initialFoldCount)        │   (Triggered right after Stage 1)    │
│                 │                   │                 │                    │
│                 ▼                   │                 ▼                    │
│  ┌───────────────────────────────┐  │  ┌────────────────────────────────┐  │
│  │ • Direct Supabase slice/RPC   │  │  │ • Fetches next batch records   │  │
│  │ • priorityImage = true        │  │  │ • Hydrates missing DB images   │  │
│  │ • loading="eager"             │  │  │ • Pre-decodes URLs in memory   │  │
│  │ • fetchPriority="high"        │  │  │   via async Image().decode()   │  │
│  └──────────────┬────────────────┘  └─────────────────┬──────────────────┘ │
│                 │                                     │                    │
│                 └──────────────────┬──────────────────┘                    │
│                                    ▼                                       │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │       IntersectionObserver Sentinel (rootMargin: "750px 0px")        │  │
│  │  • Appends pre-warmed batch instantly on scroll                      │  │
│  │  • Doubles batch size automatically when scroll velocity is high     │  │
│  │  • Subsequent cards use loading="lazy" + cached pre-decoded images   │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────────┘
```

### تفاعل المكونات وإدارة الحالة:
- **حساب هندسة الشاشة (`Viewport Grid Calculator`)**: يستجيب لتغير أبعاد النافذة (`resize` / `orientationchange`) ويحدد عدد الأعمدة والصفوف المرئية بدقة.
- **إدارة أولوية الصور (`Priority vs Lazy Image Strategy`)**: تمرير `priorityImage={index < initialFoldCount}` لكل بطاقة `ProductCard` بحيث تحصل بطاقات الشاشة الأولى فقط على `loading="eager"` و `fetchPriority="high"`، بينما تحصل بقية البطاقات على `loading="lazy"` دون إبطاء الشاشة الأولى.
- **الجلب المسبق التلقائي بعد الظهور الأول (`Immediate Next-Batch Warmup`)**: مؤقت خامل ذكي يبدأ فور عرض الدفعة الأولى بتجهيز الدفعة الثانية في الذاكرة وصورها قبل تحريك الصفحة.

# إصلاح وتطوير نظام اختيار الأقسام ووضع «جميع الأقسام» وتعدد التصنيفات في نافذة تعديل المنتج

تهدف هذه الخطة إلى معالجة الخلل البرمجي في نافذة تعديل وإضافة المنتجات (`/dashboard/products`) عند التبديل بين وضع **«جميع الاقسام» (مفعل للكل)** والأقسام الاعتيادية، مع دعم اختيار **أكثر من قسم للمنتج الواحد** بمرونة كاملة، ومزامنة حمولة البيانات مع قاعدة بيانات Supabase دون أي تعارضات.

---

## قرارات المراجعة المعتمدة (User Review & Confirmed Decisions)

> [!IMPORTANT]
> تم اعتماد التفضيلات التالية بناءً على إجاباتك المباشرة لضمان تجربة استخدام سلسة وفورية:

- **سلوك زر «جميع الاقسام» عند النقر عليه وهو مفعل مسبقاً**: إلغاء وضع التعميم (`جميع الاقسام`) فوراً وفتح قائمة الأقسام تلقائياً لاختيار قسم بديل أو أكثر بنقرة واحدة.
- **سلوك حقل البحث وقائمة الأقسام المنسدلة**: فصل نص البحث عن حالة «جميع الاقسام» بحيث تعرض القائمة المنسدلة كافة الأقسام المتاحة فوراً دون الحاجة لمسح أي نص يدوياً.
- **دعم تعدد الأقسام للمنتج الواحد (Multi-Category Selection)**: إتاحة اختيار قسم واحد أو عدة أقسام للمنتج الواحد في نفس الوقت عبر شارات تفاعلية (Interactive Category Chips) ليظهر المنتج في جميع الأقسام المختارة بسهولة تامة، مع إمكانية التبديل الفوري بين «جميع الاقسام» والأقسام المتعددة.
- **توافق قاعدة البيانات وكود SQL الجاهز للنسخ**: توفير كود SQL متكامل في نهاية التنفيذ لتحديث جدول `products` وجدول الربط `product_categories` في Supabase لدعم `is_all_categories` و`category_name` وتعدد الأقسام دون قيود تمنع الحفظ.

## 1. نظرة عامة والمفهوم الأساسي (Overview & Core Concept)

- **ما الذي يقدمه التحديث**:
  1. **إصلاح جذري لتجمد حالة القسم**: منع إعادة تهيئة النموذج (`useEffect` Reset) أثناء فتح النافذة عند تحديث الصور الكسولة في الخلفية، وإزالة الشرط المنطقي الخاطئ الذي كان يُبقي `جميع الاقسام` مفعلاً حتى بعد اختيار قسم عادي.
  2. **التبديل الذكي لزر «جميع الاقسام»**: يعمل الزر كمفتاح تبديل ثنائي (Toggle)؛ إذا كان مفعلاً ونقر المستخدم عليه، يُلغى التعميم وتُفتح قائمة الأقسام فوراً. كما أن النقر على أي قسم عادي داخل القائمة يلغي وضع «جميع الاقسام» تلقائياً ويعتمد القسم المختار.
  3. **إضافة أكثر من قسم للمنتج الواحد**: إمكانية تحديد عدة أقسام من القائمة المنسدلة (أو إنشاء قسم جديد فوراً) ليظهر كل قسم كشارة بنفسجية/زرقاء قابلة للإزالة، مع حفظها في `notes` و`category_name` وجدول الربط `product_categories`.
  4. **تحديث الحفظ في Supabase**: تمرير حقول `category_name` و`is_all_categories` و`category_id` بشكل صريح في `productToRow` لضمان مسح حالة `is_all_categories` القديمة من قاعدة البيانات عند التحول إلى أقسام محددة.

## 2. تجربة المستخدم والتصميم البصري (User Experience & Visual Design)

- **خطوات تدفق المستخدم (Key User Flows)**:
  1. **التحويل من «جميع الاقسام» إلى قسم عادي أو أكثر**:
     - عند فتح نافذة تعديل منتج مضبوط على `جميع الاقسام`، يظهر زر التعميم بحالة نشطة (`✓ مفعل للكل`) بينما يبقى حقل البحث فارغاً وجاهزاً للكتابة أو النقر.
     - بمجرد النقر على زر `جميع الاقسام` (أو النقر داخل حقل البحث)، تُفتح قائمة كافة الأقسام فوراً.
     - عند النقر على قسم عادي (مثل `بطاريات`)، يتحول المنتج فوراً من `جميع الاقسام` إلى القسم المختار، ويمكن النقر على قسم ثانٍ (مثل `شواحن`) لإضافته بجانبه.
  2. **عرض الشارات المتعددة (Multi-Category Badges)**:
     - تظهر الأقسام المختارة كشارات أنيقة قابلة للحذف (`×`) أعلى حقل البحث وفي جدول المنتجات وبطاقات الجوال.
- **الهوية البصرية والسمة (Visual Identity & Theme)**:
  - *الاتجاه الجمالي*: الحفاظ الصارم على الهوية البنفسجية الملكية الفاخرة لمتجر **أحمد بحري** (`#5b21b6`، `#1e113b`، `#160b2e`).
  - *التجاوب الكامل (Responsive Layout)*: تصميم متجاوب 100% على الهواتف والأجهزة اللوحية والحواسيب مع التفاف مرن (`flex-wrap`) للشارات والأزرار ومنع أي اقتطاع للنصوص.

## 3. القرارات التقنية والمفاضلات (Key Product Decisions & Trade-Offs)

- **القرار 1: فصل حالة الأقسام المختارة (`selectedCategories: string[]`) عن نص البحث (`categoryQuery`)**
  - *النهج المختار*: تخزين الأقسام المختارة في مصفوفة مستقلة، وإبقاء `categoryQuery` مخصصاً للبحث الفوري أو إنشاء قسم جديد فقط.
  - *لماذا*: كان وضع النص `"جميع الاقسام"` داخل حقل البحث يمنع ظهور باقي الأقسام في القائمة المنسدلة ما لم يقم المستخدم بمسح الحقل يدوياً حرفاً بحرف.
- **القرار 2: تثبيت دورة حياة `useEffect` في نافذة تعديل المنتج**
  - *النهج المختار*: ربط تهيئة حقول النموذج بمعرف المنتج وحالة الفتح (`product?.id` و`isOpen`) فقط بدلاً من كائن `product` الكامل.
  - *لماذا*: لأن نظام التحميل الكسول للصور يحدث كائن المنتج في الخلفية، مما كان يؤدي إلى إعادة ضبط النموذج ومسح اختيار المستخدم للقسم الجديد قبل الضغط على حفظ.
- **القرار 3: تمثيل الأقسام المتعددة في قاعدة البيانات بدون كسر التوافقية**
  - *النهج المختار*: حفظ الأقسام المتعددة مفصولة بفاصلة قياسية في `category_name` ووسم `الفئة: قسم1 ، قسم2` داخل `notes`، مع ربط المعرف الأساسي في `category_id` ومزامنة جدول `product_categories`.
  - *لماذا*: يضمن عمل الفلترة والبحث في كل من لوحة التحكم والمتجر العام بسرعة فورية ودون أي خطأ في قواعد بيانات PostgreSQL/Supabase.

## 4. البنية التقنية واستراتيجية البيانات (Technical Architecture & Data Strategy)

### مخطط تدفق الحالة والبيانات (Architecture & State Flow Diagram)

```
┌──────────────────────────────────────────────────────────────────────────┐
│                     Product Edit & Bulk Category UI                      │
│  ┌────────────────────────────────────────────────────────────────────┐  │
│  │ 1. Universal Toggle Button ("جميع الاقسام")                        │  │
│  │    • If Active -> Click clears universal mode & opens dropdown     │  │
│  │    • If Inactive -> Click activates universal mode & clears chips  │  │
│  └───────────────┬────────────────────────────────────┬───────────────┘  │
│                  │                                    │                  │
│                  ▼                                    ▼                  │
│  ┌───────────────────────────────────┐  ┌─────────────────────────────┐  │
│  │ 2. Selected Categories Chips      │  │ 3. Instant Search Combobox  │  │
│  │    [ بطاريات × ] [ شواحن × ]      │◄─┤    Shows ALL categories     │  │
│  │    Multi-select add/remove        │  │    without manual clearing  │  │
│  └───────────────┬───────────────────┘  └─────────────────────────────┘  │
└──────────────────┼───────────────────────────────────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                 Data Normalization & Supabase Sync Layer                 │
│  • is_all_categories : boolean (explicitly true or false)                │
│  • category_name     : "جميع الاقسام" OR "قسم 1 ، قسم 2"                  │
│  • category_id       : NULL (if universal) OR primary category UUID      │
│  • notes             : "الفئة: قسم 1 ، قسم 2" (synced cleanly)            │
└──────────────────────────────────────────────────────────────────────────┘
```

### تفاصيل ربط المكونات والحالة (Interactive Component & State Mapping)
1. **مكون نافذة المنتج (`ProductModal`)**:
   - استبدال الحالة المفردة بمصفوفة `selectedCategories: string[]` مع علم صريح `isAllCategoriesSelected: boolean`.
   - إضافة دالة `handleToggleUniversal()` لإلغاء التعميم وفتح القائمة فوراً عند النقر على الزر وهو مفعل.
   - إضافة دالة `handleToggleCategoryItem(catName)` التي تلغي وضع `جميع الاقسام` تلقائياً وتضيف/تزيل القسم من `selectedCategories` مع إبقاء القائمة متاحة لاختيار أكثر من قسم بسهولة.
2. **محول البيانات (`productToRow` و `rowToProduct` و `seo`)**:
   - تحديث `productToRow` لتضمين `category_name` و`is_all_categories` مع آلية Fallback ذكية إذا لم يكن العمود مضافاً بعد في قاعدة البيانات.
   - تحديث دوال الفلترة واستخراج الأقسام لدعم المنتجات المنتمية لعدة أقسام (`قسم 1 ، قسم 2`) دون إنشاء أقسام وهمية مدمجة أثناء المزامنة التلقائية.
3. **صفحة المنتجات (`ProductsPage`)**:
   - إصلاح استدعاء `addProduct` في `ProductsPage`، وتحديث نافذة التعديل الجماعي للقسم لدعم التبديل السلس واختيار أكثر من قسم للمنتجات المحددة.
